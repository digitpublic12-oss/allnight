# Allnight — 디자인 시스템 명세 (DESIGN.md)

> 상태: 디자인 인터뷰 Q1–Q18 완료 / 구현 참조용. 2026-11-05.
> 권장 위치: `docs/DESIGN.md` (다운로드 파일명은 `DESIGN.md`).
> 적용 범위: 1차 데스크톱 MVP의 사용자·관리자 화면. `[Later]`는 출시 범위 밖.

## 0. 문서 사용 원칙과 기존 명세의 관계

- **PRD.md**는 기능과 MVP 범위, **SITEMAP.md**는 화면·전환, **DB.md**는 데이터·시간 판정, **AGENTS.md**는 구현 승인 절차를 정의한다. 이 문서는 **시각적 표현과 UI 컴포넌트**를 정의하며 다른 문서의 기능·권한·데이터 규칙을 바꾸지 않는다.
- Claude Code는 구현 전에 `AGENTS.md` 및 작업 관련 문서를 읽고, 문서 간 충돌이 있으면 **구현을 멈추고 사용자에게 선택지와 영향 범위를 보고하여 승인받는다**. 이 문서의 권장 구현값은 무단 변경·개발 승인을 뜻하지 않는다.
- 데이터가 없거나 검증되지 않은 영업시간을 확인된 `영업 중`으로 표시하지 않는다. 시간 상태(`full`/`partial`/`unknown`/`closed`)와 데이터 검증 상태(`verification_status`)는 별개이다.
- 본문에서 **[확정]**은 Q1–Q18 인터뷰에서 확정된 방향, **[제안]**은 구체 수치·구현 편의를 위한 권장 기본값, **[확인 필요]**는 기존 문서와의 충돌 또는 외부 기술 검증이 필요한 항목이다.

## 1. 디자인 원칙 [확정]

1. **Minimal / Utilitarian:** 시각적 장식보다 정보의 빠른 파악과 실제 탐색 효율 우선.
2. **Map-first:** 지도를 화면 전체의 바탕으로 사용하고 왼쪽 검색 패널을 지도 위에 플로팅.
3. **Dense but legible:** 14px 중심의 컴팩트한 정보 밀도, 명확한 시각 계층.
4. **Trust-aware:** 영업시간의 적용 범위와 검증 상태를 정직하게 구분. 경고에는 텍스트·아이콘을 함께 사용.
5. **Quiet interaction:** 블루 포인트와 최소한의 그림자·전환 효과, 예측 가능한 동작.
6. **Accessible:** WCAG AA 수준 목표, 키보드 조작 및 OS 모션 감소 설정 존중.

## 2. 디자인 토큰

### 2.1 색상 [확정]

| 의미 | Light | Dark | 비고 |
|---|---|---|---|
| 브랜드 Primary | `#2563EB` | `#2563EB` (채운 버튼) | 중요 버튼, 선택 상태, 링크에 절제해 사용 |
| Dark 배경 | — | `#111827` | 블루 기운 있는 차콜 |
| Dark 패널 | — | `#1F2937` | 검색·상세·관리자 표면 |
| 테두리 | `#E5E7EB` | `#374151` | 기본 1px |
| Dark 링크/아이콘 강조 | — | 밝은 블루 계열 | 정확한 토큰은 대비 검증 후 확정 |
| 주의·미확인 | 앰버 계열 | 앰버 계열 | 색상 + 아이콘 + 설명 필수 |

**[제안]** 구현용 보조 토큰(확정 색상이 아님): Light 배경 `#F9FAFB`, 패널 `#FFFFFF`, 주 텍스트 `#111827`, 보조 텍스트 `#6B7280`; Dark 주 텍스트 `#F9FAFB`, 보조 텍스트 `#D1D5DB`; Dark 강조 텍스트 `#93C5FD`; 경고 배경 Light `#FFFBEB`, 텍스트 `#92400E`. 이 값들은 실제 대비 측정 후 조정한다.

**[확정]** 영업 상태의 시각 언어: `full`은 블루, `partial`은 중립색, `unknown` 및 신뢰도 주의는 앰버. `closed`는 검색 결과 최하단 별도 그룹에 표시하며 중립적인 '영업하지 않음' 문구를 쓴다. `partial`을 '전체 영업'으로 오인시키지 않는다.

### 2.2 타이포그래피 [확정]

- 글꼴: **Pretendard**, 대체 `system-ui`, sans-serif.
- 크기 스케일: **12 / 14 / 16 / 20 / 24px**. 기본 본문 **14px**.
- 굵기: Regular **400**, Medium **500**, Semibold **600**.
- [제안] 12px = 캡션·보조, 14px = 기본, 16px = 섹션 제목, 20px = 장소 상세 제목, 24px = 페이지 제목. 기본 줄 높이 1.45–1.55, 숫자 정렬이 필요한 관리자 테이블에는 tabular numerals.
- 작은 보조 문구도 WCAG AA 목표에 맞는 대비 확보. 12px보다 작은 본문은 기본적으로 사용하지 않는다.

### 2.3 간격·형태 [확정]

- 4px 기반 스케일: **4 / 8 / 12 / 16 / 24 / 32px**.
- 기본 radius: **6px**. 칩은 캡슐형 예외 허용.
- 테두리: **1px**. 카드·패널 분리에 우선 사용.
- 그림자: 플로팅 패널·지도 컨트롤·팝오버·모달에만 약하게 사용.
- 버튼 및 입력창 기본 높이: **36px**.
- [제안] 컨트롤 가로 패딩 12px, 섹션 간격 16–24px, 목록 행 세로 패딩 12px. 정확한 그림자·포커스 링 수치는 구현 전 UI 검수에서 결정.

## 3. 테마 [확정]

- 기본 테마는 OS의 light/dark 설정을 따름. 사용자는 수동으로 전환 가능하며 선택값을 유지.
- 같은 의미의 semantic token을 light/dark에 매핑. 컴포넌트별 임의 하드코딩 금지.
- 다크 모드의 블루는 용도별 밝기 조정: 채운 주요 버튼 `#2563EB`, 링크·작은 텍스트·아이콘은 더 밝은 블루 사용 가능. 대비 검증 필수.
- **지도 테마도 앱 테마에 연동**하는 것이 목표. **[확인 필요]** 카카오 지도 API가 지원하는 스타일·테마 변경 범위 검증 후 구현. 불가능한 경우 임의 CSS 필터로 지도 색을 왜곡하지 말고 대안을 사용자에게 승인받는다.

## 4. 레이아웃과 화면 크기 [확정]

- MVP는 **데스크톱 웹**. 지원 최소 viewport 너비 **1024px**; 그보다 좁으면 미지원 안내를 표시하고 모바일 전용 탐색 UI를 만들지 않음.
- 지도는 **전체 viewport 배경**, 검색·목록·상세 패널은 지도 **위에 겹쳐지는 왼쪽 400px 고정 플로팅 패널**. 분할 레이아웃으로 변경하지 않음.
- 사이드바 접기/펼치기 가능. 작은 지원 데스크톱에서도 폭 **400px 유지**.
- 검색창·핵심 필터(시간/카테고리)는 패널 상단에 고정; 장소 목록만 독립 스크롤. 고급 필터는 내부에서 펼침.
- 지도 이동은 자동 재검색하지 않음. 지도 위 **'이 지역 검색'** 버튼을 눌러 현재 영역 검색. 시간·카테고리 변경 시 검색 결과는 해당 입력의 규칙대로 갱신.
- 결과 항목 선택 시 같은 패널이 장소 상세로 전환되며 지도·검색 상태 유지. 뒤로 가면 목록, 필터, 가능한 스크롤 위치 복원.
- `/place/:id` 직접 접근과 브라우저 뒤로 가기 등은 `SITEMAP.md`의 라우팅 규칙을 따른다.

## 5. 지도 마커와 컨트롤 [확정]

- 마커는 **작고 원형**. `full`은 **채운 원**, `partial`은 **윤곽선 원**. `unknown`은 앰버와 경고 표현을 사용하되 확인된 영업으로 보이지 않게 한다.
- 선택된 마커는 크기 증가 + 윤곽선 강조. 동일 위치·밀집 마커는 클러스터링.
- 지도 줌, 현재 위치 등 컨트롤은 패널과 동일한 중립 표면, 얇은 테두리, 약한 그림자의 **플로팅 버튼**.
- '이 지역 검색'은 명확한 클릭 가능한 컨트롤. 지도 이동 직후 결과가 자동 갱신된 것처럼 오인시키지 않는다.
- 마커의 색 외에 채움/윤곽·선택 강조·텍스트 상태를 병행해 상태를 전달한다.
- [제안] 마커/클러스터의 정확한 지름·클러스터 임계값은 지도 API 동작과 실제 데이터 밀도 검증 후 결정.

## 6. 검색·시간·필터 [확정]

### 6.1 시간 선택

- **타임라인 슬라이더**를 핵심 시간 입력 UI로 사용. **30분 단위**로 스냅.
- 특정 시각 검색과 시작–종료 **범위 검색**을 모두 지원. 기본 검색은 **현재 시각(Asia/Seoul)**.
- 슬라이더 변경은 **즉시 결과에 반영**. [제안] 드래그 중 요청 폭주를 막기 위해 화면 값은 즉시 반영하되 검색 요청은 debounce 또는 최신 요청만 반영. 사용자가 '적용' 버튼을 눌러야 하는 구조로 바꾸지 않는다.
- 18:00–익일 07:00의 야간 탐색을 직관적으로 표현하되, 실제 저장 영업시간은 낮 시간도 표현할 수 있으나 공개 시간 슬라이더의 선택 범위는 18:00~익일 07:00이다. **자정 넘김과 날짜 전환**을 명확히 표시.
- **[확정]** 슬라이더는 시작 날짜 기준 18:00~익일 07:00, 30분 단위로 동작하며 특정 시각/구간 모드를 지원한다. 미래 시작 날짜 상한은 없다. 현재 시각이 격자에 맞지 않을 때의 기본값 처리만 구현 전 확인한다.
- DB의 검색 구간 `[start,end)`와 상태 `full` → `partial` → `unknown` → `closed` 순서 및 그룹별 정렬을 그대로 사용. UI가 임의로 영업 판정을 재계산하지 않는다.

### 6.2 카테고리·고급 필터

- 카테고리는 **가로 스크롤 가능한 칩**. **복수 선택** 허용. 선택 칩은 블루 계열로 강조.
- 8개 카테고리 이름·식별자는 `PRD.md`, `SITEMAP.md`, `DB.md`의 확정 데이터 정의를 사용. 표기명은 **학습·업무**로 통일하며 UI에서 별도 분류를 생성하지 않는다.
- 기본 필터는 시간·카테고리. 지역/거리, 검증 상태, 24시간 여부, 태그 등은 사이드바 안의 **접을 수 있는 고급 필터**에 배치.
- 태그 필터는 **태그 검색 + 추천 목록**. **표준 태그만 선택 가능**하며 사용자 자유 해시태그 생성 기능을 추가하지 않는다.
- 필터 변경 시 선택 상태가 명확히 보이게 하고, 검색 결과 없음 화면에서 필터 초기화 제공.

## 7. 장소 목록 [확정]

- 사진 카드가 아닌 **컴팩트한 텍스트 행**.
- 1차 정보: **장소명 + 선택 시간의 영업 상태**. 2차 정보: 카테고리 + **간략한 지역명**. 확인일은 보조 정보.
- 미확인·주의 상태는 목록에서도 **아이콘 + 앰버 + 설명/레이블**로 구분. 검증 상태와 시간 판정은 별개로 취급.
- 선택 행은 **연한 블루 배경 + 왼쪽 강조선**. Dark에서는 의미가 동일한 다크 선택 배경으로 매핑.
- 긴 장소명·주소는 **목록에서 말줄임**, 상세에서는 전체 텍스트 표시. 잘린 정보는 키보드·마우스로 접근 가능한 방식으로 확인할 수 있게 구현 권장.
- 결과는 DB 기준 `full` → `partial` → `unknown` → `closed` 그룹을 유지하며, 그룹 내 정렬도 DB 규칙을 따른다.

## 8. 장소 상세 패널 [확정, 충돌 확인 항목 포함]

- 사용자는 **사진 헤더형**을 선택. **대표 사진이 존재하면 상단에 표시**, 사진이 없거나 불러오지 못하면 **사진 영역 자체를 생략**(빈 플레이스홀더 없음).
- 장소명, 카테고리, 영업 상태·검증 상태, 확인일을 명확히 표시. 장소명 **바로 아래 주요 행동 버튼**(길찾기, 정보 수정 제안 등) 배치. 즐겨찾기는 `[Later]`이므로 MVP에서 활성화하지 않음.
- **선택한 시간의 영업 판정 결과를 상단에**, 그 아래 **주간 영업시간 정보**를 제공. 정기휴무, 여러 영업 구간, 날짜별 예외, 익일 종료를 정확히 표현.
- 나머지 주소·연락처·웹사이트·태그·사진·리뷰는 **연속 스크롤**로 제공. 별도 리뷰 탭을 새로 만들지 않음. 리뷰는 별점·리뷰 사진 없이 텍스트 중심.
- 정보가 없는 전화번호·웹사이트·사진 버튼/섹션을 무의미하게 활성화하지 않는다.
- 상세 → 검색 결과 복귀 시 기존 지도·검색어·시간·필터·목록 상태를 유지.

**[해결: Q1·Q2에서 상단 사진 배치 및 시간표 기본 접힘 확정]**

1. `SITEMAP.md` §5는 상세 상단 우선순위를 **장소명 → 영업 상태/검증 상태 → 확인일**로 정의하고 '큰 대표 사진은 상단 필수 요소가 아니다'라고 명시한다. Q10은 **사진이 있을 때 상단 대표 사진을 표시**하도록 선택했다. 사진이 *필수는 아니라는 점*은 양립하지만, **사진과 장소명 중 화면 최상단의 실제 배치 순서**는 서로 다르게 해석될 수 있다. 사용자 승인 없이 기존 SITEMAP의 우선순위를 뒤집지 말 것. 사진의 조건부 표시와 정보 우선순위를 모두 만족하는 배치 시안을 제시해 승인받는다.
2. `SITEMAP.md` §5는 **오늘 영업시간 먼저 + '전체 보기'로 주간 시간표 확장**을 명시한다. Q10은 **선택 시간 결과 상단 + 아래 주간 시간표**를 선택했다. 주간 시간표의 **기본 펼침/접힘**은 Q10에서 확정하지 않았다. MVP에서는 기존 SITEMAP의 '전체 보기' 동작을 보존하고, 기본 펼침 변경이 필요하면 사용자 승인을 받는다.
3. 상세 화면을 비롯한 기능의 MVP/Later 범위는 SITEMAP/PRD가 우선 담당한다. 이 디자인 문서로 후속 기능을 조기 활성화하지 않는다.

## 최종 검토 Q1–Q8 확정 사항 (2026-11-05)

> 이 절은 사용자 승인으로 확정된 최신 정책이다. 같은 문서 또는 다른 문서의 이전 **잠정/권장/확인 필요** 문구와 충돌하면 이 절을 우선 적용한다. 단, 구현상 추가 확인이 필요한 외부 API 제약은 검증한다.

1. **장소 상세:** 대표 사진이 있으면 뒤로가기 다음의 최상단 사진 헤더로 표시한다. 사진이 없으면 영역을 생략한다. 장소명과 선택 시간 영업 상태를 이어서 표시한다. 주간 영업시간은 기본 접힘, 사용자 조작으로 7일 시간표를 펼친다. 적용되는 특별 영업/임시 휴무 등 예외는 접힘 상태에서도 상단에 안내하고 실제 영업 판정에 반영한다.
2. **지도와 필터:** 지도 이동만으로는 재검색하지 않는다. '이 지역 검색'을 눌렀을 때 검색 영역을 변경한다. 지도만 이동한 상태에서 카테고리/태그/시간 필터를 변경해도 **마지막으로 확정된 검색 영역**을 대상으로 검색한다. 카테고리/태그는 변경 즉시 검색한다. 시간 슬라이더는 드래그 중 선택 시각 표시만 갱신하고, 놓았을 때 서버에 검색 요청한다.
3. **검색 결과 그룹 및 정렬:** `full`(전체 영업) → `partial`(일부 영업) → `unknown`(영업정보 미확인) → `closed`(선택 시간에 영업하지 않음) 순으로 **모든 그룹을 표시**한다. `full`은 확정 검색 지도 중심과의 거리순, `partial`은 선택 구간 중 실제 영업 시간의 총 길이 내림차순 후 거리순, `unknown`은 하단 별도 그룹, `closed`는 최하단 별도 그룹이다. 동일 조건의 안정적 정렬을 위해 ID 등 결정적 타이브레이커를 사용한다. 미확인 장소를 영업 중이라고 단정하지 않는다.
4. **정보 신뢰도:** 마지막 관리자 실확인 시각으로부터 **30일 초과** 시 '정보 오래됨' 경고를 표시하되 원래 그룹과 정렬은 유지한다. '영업하지 않음' 이용자 제보가 접수되면 관리자 확인 전에도 '영업 여부 제보 있음' 경고를 표시하고 기존 영업시간 판정은 유지한다. **확인일은 관리자가 실제 영업정보를 확인했을 때만** 갱신하며, 단순 제보 접수나 데이터 수정만으로 갱신하지 않는다.
5. **콘텐츠 운영:** 회원 텍스트 후기(별점/후기 사진 없음)는 작성 즉시 공개하며 신고 후 관리자 검토한다. 장소 대표 사진의 등록/변경은 관리자만 할 수 있다. 장소 신규 등록/정보 수정 제보는 승인 전 실제 장소 데이터에 반영하지 않으며, 제출자에게 접수 안내를 제공하고 **회원에게는 본인 제보의 검토 상태 조회**를 제공한다. 비회원 제보도 기존 허용 원칙을 유지하되 계정 없는 제보자에게 회원용 조회 기능을 약속하지 않는다.
6. **시간 검색:** 시작 날짜만 선택하며 종료 날짜는 자정 통과에 따라 자동 계산한다. 슬라이더 범위는 **18:00~다음 날 07:00**, 30분 단위이다. **특정 시각과 시간 구간** 검색을 모두 지원한다. 미래 날짜 검색 상한은 두지 않으며, 반복 영업시간과 등록된 날짜별 예외로 계산한다. 미등록 미래 예외는 보장하지 않는다고 안내한다. '지금' 기본값이 30분 격자와 맞지 않을 경우 실제 현재 시각을 유지할지 스냅할지는 구현 전 별도 확인이 필요하다.
7. **기술 스택:** **Next.js + TypeScript**, **Cloudflare 배포**, **카카오 지도 API**, **Supabase PostgreSQL + PostGIS / Auth / Storage** 확정. Next.js의 Cloudflare 런타임/배포 어댑터 호환성, 카카오 지도 다크 테마 지원 여부는 구현 전 기술 검증한다. 검증 없이 프레임워크를 임의 변경하지 않는다.
8. **초기 데이터:** 직접 검증한 실제 장소 **30개**를 최초 공개 목표로 한다.

**DB/API 주의:** 이전 검색 응답의 `coverageStatus: full|partial|unknown`은 `closed`를 포함하도록 확장해야 한다. 부분 영업시간의 정렬값(선택 구간과 실제 영업 구간의 교집합 총 분)을 계산·반환 또는 서버 내부 정렬 키로 사용한다. `unknown`과 `closed`는 별도 상태이며 혼합하지 않는다. 페이지네이션은 그룹·정렬 순서를 유지해야 한다.
