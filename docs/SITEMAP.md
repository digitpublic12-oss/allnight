# Allnight — SITEMAP

> Version: 1.0 · 2026-11-05 · Status: SITEMAP 인터뷰 Q1–Q14 확정
>
> 목적: Claude 구현을 위한 데스크톱 중심 화면 구조, 내비게이션, URL, 접근 권한 및 단계별 구현 범위 정의.
>
> 범위 표기: **[MVP]** 1차 구현 / **[Later]** 후속 구현. 후속 화면은 정보구조만 설계하며 1차 개발 대상이 아니다.

## 1. 제품 내비게이션 원칙

- **지도 중심 단일 화면**: `/`에서 즉시 지도와 왼쪽 탐색 패널을 표시한다. 별도 홍보용 랜딩 페이지는 만들지 않는다.
- 데스크톱에서 **왼쪽 패널 + 오른쪽 지도**를 기본 레이아웃으로 사용한다. 모바일 최적화는 이번 과제 범위에서 제외한다.
- 장소 목록, 상세, 제보, 마이페이지는 지도 위에서 패널 내용만 전환한다. 지도는 유지한다.
- 패널은 **스택 방식**으로 이동하며 뒤로 가기로 직전 패널로 복귀한다. 검색어·시간·필터·지도 위치·가능한 경우 목록 스크롤을 보존한다.
- 검색창은 검색 결과 목록 패널에서만 표시한다.
- 주요 기능은 지도 위 **플로팅 메뉴**로 진입한다. 1차 메뉴: 장소 제보, 로그인/내 계정, 다크/라이트 전환. 즐겨찾기는 후속 구현. **관리자 메뉴는 일반 UI에 노출하지 않는다**(Q12가 Q5의 관리자 메뉴 선택을 최종 변경).
- 지도 이동만으로 결과를 자동 재검색하지 않고, **‘이 지역 검색’** 버튼을 눌러 갱신한다.

## 3. 라우트 및 URL 설계

| 경로 | 화면 | 범위 | 비고 |
|---|---|---|---|
| `/` | 지도 및 검색 결과 | MVP | 첫 방문 즉시 지도 표시 |
| `/place/:placeId` | 지도 + 장소 상세 패널 | MVP | 직접 링크·공유·새로고침 지원, 지도는 장소 중심으로 이동 |
| `/admin` | 관리자 대시보드 | MVP | 관리자만 접근 가능, 일반 UI에 링크 없음 |
| `/admin/places` | 장소 관리 목록 | MVP | 세부 경로는 구현 시 확정 |
| `/admin/places/:placeId/edit` | 장소 편집 | MVP | 별도 편집 화면 |
| `/admin/submissions` | 제보 승인 관리 | MVP | 신규/수정/처리 완료 탭 |
| `/admin/reviews` | 리뷰 관리 | MVP |  |
| `/admin/taxonomy` | 카테고리·태그 관리 | MVP |  |

- 검색어, 선택 시간(시점 또는 구간), 카테고리·태그·검증 상태 등 필터는 URL **쿼리 파라미터**로 직렬화한다. 실제 키 이름은 개발 시 정하되, 복원과 공유가 가능해야 한다.
- `/place/:placeId`에서도 쿼리 파라미터로 검색 상태를 유지한다.
- 브라우저 뒤로/앞으로 가기는 패널 스택을 단계별로 반영한다. 새로고침 시 URL이 표현하는 검색 조건·선택 장소를 복원한다.
- 로그인/회원가입, 제보, 마이페이지 등은 **별도 페이지 이동이 아닌 모달/패널 상태**로 다룬다. 다만 브라우저 히스토리와 패널 스택이 일치하도록 구현한다.
- 존재하지 않거나 삭제된 장소 URL은 별도 404 페이지 대신 **지도 + ‘장소를 찾을 수 없습니다’ 안내 패널**을 표시한다.
- 관리자 세부 URL은 구현을 위한 **제안 경로**이며 `/admin` 외 세부 경로 문자열은 인터뷰에서 확정하지 않았다.

## 4. 지도·검색 패널 [MVP]

### 기본 구조
1. 왼쪽 상단: 장소명/키워드 검색, 지역 설정, 시간 선택.
2. 기본 필터는 상시 노출, 추가 필터는 펼치기/접기.
3. 왼쪽 아래: 결과 목록. 오른쪽: 지도 마커.
4. 지도 이동 시 자동 검색하지 않음. 지도 위 ‘이 지역 검색’ 클릭 시 현재 지도 영역을 기준으로 결과 갱신.
5. 결과에서 장소를 클릭하면 왼쪽 패널이 상세 화면으로 전환되고 지도는 유지.

### 검색·정렬 요구사항
- 기본 시간 조건은 **현재 시각**. 특정 시점 또는 시작–종료 구간 검색 지원.
- 자정을 넘기는 구간과 심야 영업시간 처리.
- 구간 검색 시 **조금이라도 겹치는 장소를 포함**, 전체 구간 내내 영업하는 장소를 우선 정렬.
- 필터: 카테고리, 위치/거리, 표준 태그·편의시설, 검증 상태, 24시간 영업, 정렬.
- 카테고리: 음식·카페 / 쇼핑·생활 / 학습·업무 / 의료·응급 / 여가·문화 / 운동·건강 / 교통·이동 / 기타.
- 태그는 관리자 정의 표준 태그만 사용. 사용자 자유 해시태그 기능 없음.
- 결과 없음: 조건 변경 안내 + 필터 초기화 버튼.
- 미확인 장소: 검색 결과에 포함하되 **영업정보 미확인 경고**와 확인 상태·확인일 표시. 미확인 영업시간을 확정적으로 ‘영업 중’이라 단정하지 않는다.
- 로딩 오류: 오류 안내 + 다시 시도, 기존 상태 유지.

## 5. 장소 상세 패널 [MVP]

**상단 우선순위**: 뒤로가기 → 대표 사진(있을 때만) → 장소명 → 선택 시간 영업 상태/검증 상태 → 마지막 영업정보 확인일. 사진이 없으면 영역을 생략한다.

- 카테고리, 주소, 지도 위치, 길찾기.
- **선택 시간 영업 판정을 먼저 표시**하고, 적용되는 날짜별 예외·임시 휴무는 항상 상단에 안내한다. 주간 시간표는 기본 접힘이며 ‘전체 보기’로 요일별 영업시간·정기 휴무·24시간·브레이크타임·자정 이후 영업을 펼친다.
- 연락처·웹사이트·장소 사진·표준 태그 등은 데이터가 있을 때 표시.
- 상세 동작: **길찾기 / 즐겨찾기 [Later] / 정보 수정 제보 / 리뷰 작성**. 즐겨찾기 버튼은 후속 단계에서 활성화하거나 MVP에서는 비노출 처리한다.
- 리뷰는 장소 정보 **아래에 연속 배치**. 별도 리뷰 탭 불필요.
- 리뷰는 **별점 없이 텍스트**, 선택적 ‘실제로 영업 중이었는지’ 제보. 리뷰 사진 첨부 없음. 회원은 자신의 리뷰 작성·수정·삭제 가능.
- 정보 수정 제보를 누르면 현재 장소 정보를 채운 수정 패널로 진입.
- 뒤로 가기는 원래 검색 목록·필터·지도 상태를 복원.

## 6. 신규 장소 제보·정보 수정 패널 [MVP]

### 신규 장소 제보
- 왼쪽 패널의 **한 화면 스크롤 폼**으로 구성하며 단계별 마법사 형태를 사용하지 않는다.
- 필수: 장소명, 주소/위치, 카테고리, 요일별 영업시간.
- 위치는 **주소·장소명 검색으로 선택**. 지도 클릭을 통한 위치 지정은 지원하지 않는다.
- 비회원도 로그인 없이 제출 가능. 비회원 연락 이메일은 선택 사항.
- 유사한 기존 장소를 제시해 중복 제보를 방지하고, 기존 장소라면 수정 제보로 유도.
- 제출 즉시 공개하지 않고 관리자 승인 대기 상태로 저장.
- 제출 성공: 접수 완료 안내 → 기존 지도·검색 화면 복귀.

### 정보 수정 제보
- 기존 장소의 정보가 미리 채워진 폼에서 수정할 항목만 변경.
- 관리자 승인 전 원본 데이터는 변경하지 않음.
- 제보 접수 후 해당 장소에 ‘정보 수정 제보 접수’ 주의 문구를 노출할 수 있으며, 이는 수정 내용이 검증됐다는 뜻이 아님.
- 폼에 입력 내용이 있을 때 뒤로 가기/닫기 시 **나가기 확인창** 표시. 자동 임시 저장은 필수 아님.

## 7. 로그인·회원가입 [MVP]

- 지도 위 **중앙 모달**, 이메일·비밀번호 기반 Supabase Auth.
- 비회원도 탐색·장소 상세·장소 신규/수정 제보 가능.
- 리뷰 작성 등 회원 전용 작업 진입 시 로그인 모달을 표시하고, 로그인 성공 후 **원래 작업으로 복귀**.
- 로그아웃해도 지도 위치·검색어·시간·필터를 유지. 회원 전용 패널은 닫음.
- 즐겨찾기와 마이페이지는 후속 구현 대상. 회원 전용 기능에 대한 권한 검사는 UI와 서버/DB 양쪽에서 수행.

## 8. 즐겨찾기·마이페이지 [Later]

- 즐겨찾기: 지도 위 플로팅 진입점 → 왼쪽 패널에 저장한 장소 목록 → 선택 시 같은 패널에서 장소 상세. 로그인 필요.
- 마이페이지: **메뉴형** 홈 → 내 리뷰 / 즐겨찾기 / 내 제보 내역 / 프로필 설정.
- 내 리뷰 선택 시 해당 장소 상세로 이동하고 자신의 리뷰 위치를 보여줌.
- 내 제보 내역: 접수 내용, 처리 상태(접수·검토 중·승인·반려), 반려 사유.
- 비회원 제보는 계정과 자동 연결되지 않으므로 회원 마이페이지 내역과 구분해야 함.
- 후속 화면의 구조만 문서화하며 **MVP에서 빈 메뉴를 활성화하지 않는다**.

## 9. 관리자 `/admin` [MVP]

### 레이아웃
- 일반 지도 셸과 분리된 별도 관리자 화면.
- **왼쪽 사이드바 메뉴**: 운영 현황, 장소 관리, 제보 승인, 리뷰 관리, 카테고리/태그 관리.
- 진입 첫 화면은 **운영 현황 대시보드**: 장소 수, 승인 대기, 수정 제보, 미확인 장소 등 요약 및 최근 접수 목록.
- 장소 관리: 목록·검색·신규 등록·편집·삭제·검증 상태 관리. 장소 수정은 **별도 편집 화면**.
- 제보 승인: **하나의 화면 안에서 신규 장소 / 정보 수정 / 처리 완료 탭**. 승인·반려·반려 사유 관리.
- 리뷰 관리: 부적절한 리뷰 검토 및 관리.
- 카테고리·태그 관리: 관리자 정의 분류 체계 유지.
- 회원 관리 메뉴는 만들지 않음.

### 관리자 접근
- 일반 사용자 플로팅 메뉴에는 **관리자 링크를 노출하지 않음**. `/admin` 직접 주소 입력으로 접근.
- 비로그인 사용자가 `/admin`에 접근하면 로그인 절차를 제공하되, 로그인 후에도 관리자 권한 검증 필수.
- 로그인한 일반 회원 등 권한 없는 사용자는 **접근 권한 없음** 화면과 지도 돌아가기 동작 제공.
- 관리자 권한은 UI 숨김만으로 처리하지 말고 서버 및 Supabase RLS에서 강제.

## 10. 공통 상태·예외 처리 [MVP]

| 상황 | 동작 |
|---|---|
| 검색 결과 없음 | 안내 메시지 + 필터 초기화 |
| 영업정보 미확인 | 결과에 포함 + 경고·검증 상태 표시 |
| 지도/API/DB 로딩 실패 | 오류 안내 + 재시도, 검색·입력 상태 보존 |
| 제보 작성 중 이탈 | 입력값 존재 시 확인창 |
| 삭제/없는 장소 URL | 지도 유지 + 장소 없음 안내 패널 |
| 비회원의 리뷰 작성 | 로그인 모달 후 원래 작업 복귀 |
| 일반 회원의 `/admin` 접근 | 권한 없음 화면 |
| 로그아웃 | 지도·검색 상태 유지 |
| 패널 뒤로 가기 | 이전 패널 복원, 가능한 검색 스크롤 위치 유지 |

## 11. 화면 전환 흐름

```text
[지도 + 검색 목록]
  ├─ 장소 선택 → [장소 상세]
  │                  ├─ 정보 수정 → [기존 정보가 채워진 수정 제보] → [접수 안내] → [지도]
  │                  └─ 리뷰 작성 → (비회원이면 [로그인 모달]) → [리뷰 작성]
  ├─ 플로팅 '장소 제보' → [신규 장소 제보] → [접수 안내] → [지도]
  ├─ 플로팅 '로그인' → [중앙 로그인/회원가입 모달] → [기존 화면]
  ├─ 플로팅 '테마' → [현재 화면 유지하며 테마 전환]
  ├─ 즐겨찾기 [Later] → [저장 장소 목록] → [장소 상세]
  └─ 마이페이지 [Later] → [메뉴 홈] → [하위 화면]

[/admin 직접 접근] → [로그인·관리자 권한 확인]
  ├─ 관리자 → [대시보드] → [장소 관리 / 제보 승인 / 리뷰 / 분류 관리]
  └─ 비관리자 → [접근 권한 없음]
```

## 12. 구현 우선순위와 인수 기준

### 1차 필수 [MVP]
1. 지도·검색·시간 필터·‘이 지역 검색’·검색 URL 복원.

4. 비회원 신규 장소 제보·기존 장소 정보 수정 제보·관리자 승인 대기.
5. 텍스트 리뷰 작성·수정·삭제 및 선택적 실제 영업 여부 제보.

7. 다크/라이트 테마 전환.
8. 오류·빈 상태·권한 없음·입력 이탈 확인 및 브라우저 히스토리 동작.

- Q5에서 관리자 페이지 메뉴 항목을 선택했으나, **Q12에서 'URL 직접 접근만'으로 변경**했으므로 관리자 메뉴는 일반 화면에서 숨긴다.

## 최종 검토 Q1–Q8 확정 사항 (2026-11-05)

> 이 절은 사용자 승인으로 확정된 최신 정책이다. 같은 문서 또는 다른 문서의 이전 **잠정/권장/확인 필요** 문구와 충돌하면 이 절을 우선 적용한다. 단, 구현상 추가 확인이 필요한 외부 API 제약은 검증한다.

1. **장소 상세:** 대표 사진이 있으면 뒤로가기 다음의 최상단 사진 헤더로 표시한다. 사진이 없으면 영역을 생략한다. 장소명과 선택 시간 영업 상태를 이어서 표시한다. 주간 영업시간은 기본 접힘, 사용자 조작으로 7일 시간표를 펼친다. 적용되는 특별 영업/임시 휴무 등 예외는 접힘 상태에서도 상단에 안내하고 실제 영업 판정에 반영한다.
2. **지도와 필터:** 지도 이동만으로는 재검색하지 않는다. '이 지역 검색'을 눌렀을 때 검색 영역을 변경한다. 지도만 이동한 상태에서 카테고리/태그/시간 필터를 변경해도 **마지막으로 확정된 검색 영역**을 대상으로 검색한다. 카테고리/태그는 변경 즉시 검색한다. 시간 슬라이더는 드래그 중 선택 시각 표시만 갱신하고, 놓았을 때 서버에 검색 요청한다.
3. **검색 결과 그룹 및 정렬:** `full`(전체 영업) → `partial`(일부 영업) → `unknown`(영업정보 미확인) → `closed`(선택 시간에 영업하지 않음) 순으로 **모든 그룹을 표시**한다. `full`은 확정 검색 지도 중심과의 거리순, `partial`은 선택 구간 중 실제 영업 시간의 총 길이 내림차순 후 거리순, `unknown`은 하단 별도 그룹, `closed`는 최하단 별도 그룹이다. 동일 조건의 안정적 정렬을 위해 ID 등 결정적 타이브레이커를 사용한다. 미확인 장소를 영업 중이라고 단정하지 않는다.
4. **정보 신뢰도:** 마지막 관리자 실확인 시각으로부터 **30일 초과** 시 '정보 오래됨' 경고를 표시하되 원래 그룹과 정렬은 유지한다. '영업하지 않음' 이용자 제보가 접수되면 관리자 확인 전에도 '영업 여부 제보 있음' 경고를 표시하고 기존 영업시간 판정은 유지한다. **확인일은 관리자가 실제 영업정보를 확인했을 때만** 갱신하며, 단순 제보 접수나 데이터 수정만으로 갱신하지 않는다.
5. **콘텐츠 운영:** 회원 텍스트 후기(별점/후기 사진 없음)는 작성 즉시 공개하며 신고 후 관리자 검토한다. 장소 대표 사진의 등록/변경은 관리자만 할 수 있다. 장소 신규 등록/정보 수정 제보는 승인 전 실제 장소 데이터에 반영하지 않으며, 제출자에게 접수 안내를 제공하고 **회원에게는 본인 제보의 검토 상태 조회**를 제공한다. 비회원 제보도 기존 허용 원칙을 유지하되 계정 없는 제보자에게 회원용 조회 기능을 약속하지 않는다.
6. **시간 검색:** 시작 날짜만 선택하며 종료 날짜는 자정 통과에 따라 자동 계산한다. 슬라이더 범위는 **18:00~다음 날 07:00**, 30분 단위이다. **특정 시각과 시간 구간** 검색을 모두 지원한다. 미래 날짜 검색 상한은 두지 않으며, 반복 영업시간과 등록된 날짜별 예외로 계산한다. 미등록 미래 예외는 보장하지 않는다고 안내한다. '지금' 기본값이 30분 격자와 맞지 않을 경우 실제 현재 시각을 유지할지 스냅할지는 구현 전 별도 확인이 필요하다.
7. **기술 스택:** **Next.js + TypeScript**, **Cloudflare 배포**, **네이버 지도 API**, **Supabase PostgreSQL + PostGIS / Auth / Storage** 확정. Next.js의 Cloudflare 런타임/배포 어댑터 호환성, 네이버 지도 다크 테마 지원 여부는 구현 전 기술 검증한다. 검증 없이 프레임워크를 임의 변경하지 않는다.
8. **초기 데이터:** 직접 검증한 실제 장소 **30개**를 최초 공개 목표로 한다.

**DB/API 주의:** 이전 검색 응답의 `coverageStatus: full|partial|unknown`은 `closed`를 포함하도록 확장해야 한다. 부분 영업시간의 정렬값(선택 구간과 실제 영업 구간의 교집합 총 분)을 계산·반환 또는 서버 내부 정렬 키로 사용한다. `unknown`과 `closed`는 별도 상태이며 혼합하지 않는다. 페이지네이션은 그룹·정렬 순서를 유지해야 한다.
