# Allnight — 제품 요구사항 문서 (PRD)

- 문서 상태: 초안 v0.1
- 작성 기준: 기획 인터뷰 Q1~Q20
- 프로젝트 유형: 대학교 웹 시스템 개발 과제 / 향후 서비스 확장 가능
- 대상 플랫폼: 데스크톱 웹 (모바일 전용 화면 구현은 이번 과제 범위 밖)

> **수업 시연 범위 (사용자 결정, 2026-11-05):** 이 문서의 1차(P0) 범위 중 **로그인 없이 지도·시간 검색과 장소 상세 보기만** 먼저 만든다. 장소 데이터는 Supabase에서 직접 입력한다. 회원·로그인, 제보, 리뷰, 관리자 화면은 이후 업데이트로 미루며, 요구사항 자체는 이 문서에 그대로 유지한다. 상세: `docs/PROGRESS.md` "시연 범위".

## 1. 제품 개요

**Allnight**는 야간(기본 탐색 범위 18:00~익일 07:00)에도 이용할 수 있는 장소와 서비스를 찾아주는 전국 단위 웹 서비스다. 일반 지도 서비스의 영업시간 정보가 실제 운영 현황과 다를 수 있다는 문제를 해결하기 위해, 시간대 기반 검색과 영업정보 확인 상태·확인일·사용자 오류 제보를 핵심 경험으로 제공한다.

### 1.1 해결할 문제
- 일반 장소 검색 서비스에서 야간 영업 장소를 시간대별로 탐색하기 어렵다.
- 표시된 영업시간이 최신인지 확인하기 어렵고, 실제 운영시간과 불일치할 수 있다.
- 자정을 넘는 영업, 브레이크타임, 임시휴무 등을 반영한 검색이 필요하다.

### 1.2 주요 사용자
- 늦은 시간 공부하거나 작업할 공간을 찾는 사람
- 야간 근무자 및 교대근무자
- 야간에 음식점·생활 서비스·의료·교통 등을 급히 찾는 사람

### 1.3 제품 원칙
1. **시간 우선:** 장소의 유명세보다 원하는 시간에 이용 가능한지를 우선한다.
2. **확인 상태의 투명성:** 확인되지 않은 영업정보를 확인된 것처럼 표현하지 않는다.
3. **간편한 참여:** 비회원도 신규 장소와 정보 오류를 제보할 수 있다.
4. **관리자 검토:** 제보가 실제 장소 데이터에 반영되기 전 관리자 검토를 거친다.
5. **실용적 인터페이스:** 장소 탐색에 필요한 정보를 간결하게 보여준다.

## 2. 범위와 우선순위

### 2.1 제출 필수 (P0)
- 전국 장소 검색 및 데스크톱 지도·목록 분할 화면
- 특정 시각 및 시간 구간 기반 영업 검색
- 카테고리·지역/거리·태그/편의시설·확인 상태·24시간 영업 필터와 정렬
- 장소 상세 화면, 영업시간 및 확인 상태·마지막 확인일
- 이메일/비밀번호 회원가입 및 로그인
- 회원·비회원 신규 장소 제보, 기존 장소 정보 수정 제보
- 관리자 승인·반려, 장소 CRUD, 영업정보·리뷰·카테고리·태그 관리
- 회원의 텍스트 리뷰 작성·조회·수정·삭제 및 선택적 실제 영업 여부 기록
- 관리자 운영 현황 대시보드
- 공개 URL 배포
- 실제 장소 약 30개 초기 등록 (확인·미확인 혼재 가능, 상태 표시 필수)

### 2.2 후속 구현 (P1)
- 장소 즐겨찾기 및 저장 목록
- 회원 마이페이지: 내 제보 내역, 프로필 설정 등
- 모바일 전용 탐색 UX (지도/목록 전환)

> **범위 주의:** Q15에서 회원 기능으로 선택한 즐겨찾기·내 제보 내역·프로필 설정은 제품 요구사항에는 포함하지만, Q16에서 제출 필수 기능으로 선택하지 않았으므로 P1로 배치한다. 내 리뷰 관리 기능은 P0의 리뷰 수정·삭제 기능으로 포함한다.

### 2.3 명시적 제외
- 별점/평점 시스템 및 평점 정렬
- 리뷰 사진 첨부
- 사용자 자유 해시태그 생성 (관리자 지정 태그만 사용)
- 사용자 간 채팅, 체크인
- 일반 회원 관리용 관리자 기능 (이번 과제 범위에서 제외)
- 모바일 전용 화면 구현

## 3. 역할과 권한

| 기능 | 비회원 | 로그인 회원 | 관리자 |
|---|---|---|---|
| 장소 검색·상세·리뷰 열람 | 가능 | 가능 | 가능 |
| 신규 장소 제보 | 가능 | 가능 | 가능 |
| 기존 장소 수정 제보 | 가능 | 가능 | 가능 |
| 리뷰 작성·수정·삭제 | 불가 | 본인 리뷰 | 운영상 관리 가능 |
| 장소 원본 데이터 직접 수정 | 불가 | 불가 | 가능 |
| 제보 승인·반려 | 불가 | 불가 | 가능 |
| 확인 상태·태그·카테고리 관리 | 불가 | 불가 | 가능 |

- 비회원 제보의 조회·추적 방식은 별도 구현 대상으로 확정되지 않았다.
- 관리자 권한은 일반 사용자 권한과 분리하고 서버 측 및 DB 접근 정책으로 강제한다.

## 4. 사용자 경험 및 화면

### 4.1 주요 화면
1. **탐색/검색:** 왼쪽 검색·필터·장소 목록, 오른쪽 네이버 지도 및 장소 핀
2. **장소 상세:** 주소·위치·길찾기, 요일별 영업시간, 확인 상태·확인일, 연락처·사이트, 태그·편의시설, 사진(있는 경우), 리뷰, 임시휴무/예외 시간, 오류 제보 진입점
3. **신규 장소 제보:** 필수 정보 입력, 중복 후보 확인, 제출 완료 안내
4. **기존 장소 수정 제보:** 기존 값과 수정 제안 입력, 관리자 검토 안내
5. **회원가입/로그인:** 이메일·비밀번호 기반 인증
6. **리뷰 작성/관리:** 별점 없는 텍스트 리뷰, 실제 방문 시 영업 여부 선택 기록
7. **관리자:** 운영 현황, 장소 CRUD, 신규 제보·수정 제보 검토, 확인 상태 관리, 리뷰·카테고리·태그 관리
8. **후속:** 즐겨찾기, 내 제보 내역, 프로필 설정, 모바일 지도/목록 전환

### 4.2 디자인 방향
- 다크·라이트 모드 전환 지원
- 미니멀하고 실용적인 시각 언어
- 블루 계열 포인트 컬러
- 장식보다 정보 계층, 가독성, 검색·필터 조작성을 우선
- 데스크톱 웹 우선. 모바일 전용 UI는 후속 구현

## 5. 검색과 영업시간 판정

### 5.1 시간 검색
- **특정 시각 검색:** 기본값은 현재 시각(한국 표준시, Asia/Seoul). 지정 시각에 영업 중인 장소를 표시한다.
- **시간 구간 검색:** 사용자가 시작·종료 시각을 선택한다. 해당 구간과 **일부라도 겹쳐 영업하는 장소**를 포함한다.
- 선택 구간 **전체를 영업하는 장소를 먼저** 정렬한다.
- 자정이 넘어가는 시간 범위를 정확히 처리한다.
- 야간 장소 탐색이 제품의 중심이지만, 특정 시각·구간 검색과의 관계는 구현 시 일관되게 정의한다.

### 5.2 영업시간 모델
- 요일별 영업시간을 저장한다.
- 요일별 정기휴무 및 24시간 영업을 지정할 수 있다.
- 하루에 여러 영업 구간을 등록할 수 있다(예: 브레이크타임).
- 공휴일·임시휴무·특별 영업시간 등 날짜별 예외를 지원한다.
- 자정 이후 종료되는 구간은 날짜 경계를 포함해 계산한다.
- 예외 영업시간은 정기 영업시간보다 우선 적용한다.

### 5.3 검색 필터 및 정렬
- 카테고리
- 지역·거리
- 관리자 지정 태그·편의시설
- 영업정보 확인 상태
- 24시간 영업 여부
- 정렬: 선택 구간 전체 영업 우선, 거리 등. **별점 정렬 없음.**
- 세부 정렬 옵션과 우선순위는 구현 시 UI 명세에서 최종 확정한다.

### 5.4 카테고리
음식점·카페 / 쇼핑·생활 / 학습·업무 / 의료·응급 / 여가·문화 / 운동·건강 / 교통·이동 / 기타

### 5.5 태그
- 관리자가 정의한 표준 태그만 장소에 연결한다.
- 사용자 자유 태그 및 유사 태그 자동 추천은 구현하지 않는다.

## 6. 장소 데이터와 상세 정보

### 6.1 장소 기본 정보
- 장소명, 카테고리
- 주소, 지도 좌표, 길찾기
- 요일별 영업시간 및 날짜별 예외
- 영업 상태(시간 계산 결과) 및 영업정보 확인 상태
- 마지막 영업정보 확인일
- 전화번호, 웹사이트(있으면)
- 관리자 지정 태그·편의시설
- 리뷰
- 장소 사진(있는 경우; 리뷰 사진과 구분)
- 휴무·임시 영업 변경 정보

정보가 없는 선택 항목은 허위 값으로 채우지 않고 미등록 상태로 표현한다.

### 6.2 지도 연동
- 네이버 지도 API로 지도, 핀, 좌표·위치 탐색 등을 구현한다.
- **영업시간의 기준 데이터는 Allnight 자체 DB**이며 지도 API에서 가져온 영업시간을 무조건 신뢰하거나 자동 덮어쓰지 않는다.
- API 키, 사용량·요금, 도메인 등록, 서비스 이용 약관은 개발 착수 시 확인한다.

## 7. 영업정보 신뢰성 정책

### 7.1 확인 상태
- **확인됨:** 관리자가 확인된 정보로 지정한 상태
- **확인 필요:** 재확인 필요성이 있는 상태
- **미확인:** 검증되지 않은 상태

각 장소에 마지막 확인 날짜를 표시한다. **시간 경과만으로 상태를 자동 변경하지 않는다.** 관리자가 상태를 변경할 수 있다.

### 7.2 오류 제보
1. 회원·비회원이 기존 장소의 오류 또는 변경 사항을 제보한다.
2. 제보가 접수되면 장소 상세에 **'정보 수정 제보 접수'** 주의 문구를 즉시 표시한다.
3. 기존 공식 장소 정보는 즉시 변경하지 않는다.
4. 관리자가 제보를 승인하면 정보를 수정한다. 확인일은 별도로 관리자가 실제 영업정보를 확인한 경우에만 갱신한다.
5. 반려 시 원본 정보를 유지한다. 주의 표시의 해제 조건은 승인/반려 처리 및 미해결 제보 존재 여부를 기준으로 구현한다.

**주의:** '확인됨'은 현재 실제 영업을 보장하는 문구가 아니다.

## 8. 장소 제보

### 8.1 신규 장소 제보
**필수:** 장소명, 주소·지도 위치, 카테고리, 요일별 영업시간

**선택:** 전화번호/웹사이트, 태그·편의시설, 제보 근거, 비회원 이메일 등

- 신규 제보는 승인 대기 상태로 저장한다.
- 관리자가 승인해야 공개 장소 목록에 반영한다.
- 입력 중 기존 장소와 유사한 후보를 보여주고, 동일 장소라면 신규 등록 대신 수정 제보로 안내한다.
- 중복 후보 표시가 곧 무조건적인 제보 차단을 뜻하지는 않는다.

### 8.2 수정 제보
- 누구나 기존 장소의 정보 수정을 제안할 수 있다.
- 수정 요청은 승인 전까지 원본 데이터에 반영하지 않는다.
- 접수 즉시 해당 장소에 주의 표시를 노출한다.

### 8.3 제보 상태
`대기 → 승인 또는 반려`를 기본으로 한다. 처리 일시, 처리 관리자, 검토 의견 등 운영에 필요한 기록을 보관한다.

## 9. 리뷰

- **별점 없음.** 리뷰는 텍스트 기반이다.
- 실제 방문 당시 영업 여부 기록은 **선택 사항**이다.
- 리뷰 사진 첨부는 지원하지 않는다.
- 리뷰 작성은 로그인 회원만 가능하다.
- 회원은 자신의 리뷰를 수정·삭제할 수 있다.
- 관리자는 부적절한 리뷰를 숨기거나 삭제할 수 있다.
- 사용자 리뷰의 영업 여부 기록은 참고 정보이며 공식 영업시간을 자동 변경하지 않는다.
- 초기 Q9에서 고려한 '영업정보 관련 평가'는 별점 삭제 결정에 맞춰 **텍스트 및 선택적 영업 여부 기록**으로 구현한다.

- 기존 장소 수정 제안 검토
- 영업정보 확인 상태 및 확인일 관리
- 리뷰 관리
- 카테고리·태그 관리
- 운영 현황 대시보드: 전체 장소 수, 승인 대기 제보 수, 수정 제보 수, 리뷰 수 등
- 회원 제재/회원 목록 관리 기능은 이번 과제 범위에서 제외

## 12. 초기 데이터와 운영

- 전국 검색을 지원하되, 최초 등록 데이터는 **실제 장소 약 30개**를 목표로 한다.
- 등록 장소는 일부 지역에 편중될 수 있다. 검색 결과가 없을 때는 명확한 빈 상태와 장소 제보 진입점을 제공한다.
- 확인·미확인 장소를 모두 등록할 수 있으나 확인 상태를 반드시 표시한다.
- 실재 장소 정보를 사용하고, 확인하지 않은 영업시간을 검증된 것으로 표시하지 않는다.

## 13. 기술 구성 (잠정)

| 항목 | 결정 |

| 웹 프레임워크 | Next.js + TypeScript **확정** — Cloudflare 배포 어댑터 호환성은 구현 전 검증 |

| DB·인증 | Supabase (PostgreSQL / Auth) |

- 공개 클라이언트에 서비스 관리자 비밀키를 노출하지 않는다.
- 비회원 제보에는 기본적인 입력 검증·스팸/남용 방지 대책이 필요하다.
- 운영 환경의 시간대는 한국 표준시를 기준으로 명확히 처리한다.

## 15. 주요 사용자 흐름

### 15.1 야간 장소 검색
1. 사용자가 검색어 또는 지역을 입력한다.
2. 특정 시각(기본 현재 시각) 또는 시간 구간을 선택한다.
3. 카테고리·태그·확인 상태 등 필터를 적용한다.
4. 목록과 지도에 검색 결과가 함께 표시된다.
5. 전체 구간 영업 장소를 우선 확인하고 상세 정보를 연다.
6. 영업시간, 마지막 확인일, 오류 제보 유무를 확인한다.

### 15.2 신규 장소 제보
1. 사용자가 제보 화면을 연다(로그인 불필요).
2. 장소명·위치·카테고리·요일별 시간을 입력한다.
3. 유사 장소 후보가 있으면 기존 장소 수정 제보로 안내한다.
4. 신규 제보를 제출하면 승인 대기 상태가 된다.
5. 관리자 승인 후 검색 결과에 공개된다.

### 15.3 영업정보 오류 제보
1. 사용자가 장소 상세에서 수정 제보를 제출한다.
2. 장소에 수정 제보 접수 주의 표시가 뜬다.
3. 관리자가 검토 후 승인 또는 반려한다.
4. 승인 시 DB 정보가 갱신되고 주의 표시 상태를 재계산한다.

## 16. 제출 완료 기준 (Acceptance Criteria)

1. 공개 URL에서 데스크톱 웹에 접속할 수 있다.

8. 비회원도 장소 신규/수정 제보를 제출할 수 있고 승인 전 원본 데이터는 변경되지 않는다.

## 최종 검토 Q1–Q8 확정 사항 (2026-11-05)

> 이 절은 사용자 승인으로 확정된 최신 정책이다. 같은 문서 또는 다른 문서의 이전 **잠정/권장/확인 필요** 문구와 충돌하면 이 절을 우선 적용한다. 단, 구현상 추가 확인이 필요한 외부 API 제약은 검증한다.

1. **장소 상세:** 대표 사진이 있으면 뒤로가기 다음의 최상단 사진 헤더로 표시한다. 사진이 없으면 영역을 생략한다. 장소명과 선택 시간 영업 상태를 이어서 표시한다. 주간 영업시간은 기본 접힘, 사용자 조작으로 7일 시간표를 펼친다. 적용되는 특별 영업/임시 휴무 등 예외는 접힘 상태에서도 상단에 안내하고 실제 영업 판정에 반영한다.
2. **지도와 필터:** 지도 이동만으로는 재검색하지 않는다. '이 지역 검색'을 눌렀을 때 검색 영역을 변경한다. 지도만 이동한 상태에서 카테고리/태그/시간 필터를 변경해도 **마지막으로 확정된 검색 영역**을 대상으로 검색한다. 카테고리/태그는 변경 즉시 검색한다. 시간 슬라이더는 드래그 중 선택 시각 표시만 갱신하고, 놓았을 때 서버에 검색 요청한다.
3. **검색 결과 그룹 및 정렬:** `full`(전체 영업) → `partial`(일부 영업) → `unknown`(영업정보 미확인) → `closed`(선택 시간에 영업하지 않음) 순으로 **모든 그룹을 표시**한다. `full`은 확정 검색 지도 중심과의 거리순, `partial`은 선택 구간 중 실제 영업 시간의 총 길이 내림차순 후 거리순, `unknown`은 하단 별도 그룹, `closed`는 최하단 별도 그룹이다. 동일 조건의 안정적 정렬을 위해 ID 등 결정적 타이브레이커를 사용한다. 미확인 장소를 영업 중이라고 단정하지 않는다.
4. **정보 신뢰도:** 마지막 관리자 실확인 시각으로부터 **30일 초과** 시 '정보 오래됨' 경고를 표시하되 원래 그룹과 정렬은 유지한다. '영업하지 않음' 이용자 제보가 접수되면 관리자 확인 전에도 '영업 여부 제보 있음' 경고를 표시하고 기존 영업시간 판정은 유지한다. **확인일은 관리자가 실제 영업정보를 확인했을 때만** 갱신하며, 단순 제보 접수나 데이터 수정만으로 갱신하지 않는다.
5. **콘텐츠 운영:** 회원 텍스트 후기(별점/후기 사진 없음)는 작성 즉시 공개하며 신고 후 관리자 검토한다. 장소 대표 사진의 등록/변경은 관리자만 할 수 있다. 장소 신규 등록/정보 수정 제보는 승인 전 실제 장소 데이터에 반영하지 않으며, 제출자에게 접수 안내를 제공하고 **회원에게는 본인 제보의 검토 상태 조회**를 제공한다. 비회원 제보도 기존 허용 원칙을 유지하되 계정 없는 제보자에게 회원용 조회 기능을 약속하지 않는다.
6. **시간 검색:** 시작 날짜만 선택하며 종료 날짜는 자정 통과에 따라 자동 계산한다. 슬라이더 범위는 **18:00~다음 날 07:00**, 30분 단위이다. **특정 시각과 시간 구간** 검색을 모두 지원한다. 미래 날짜 검색 상한은 두지 않으며, 반복 영업시간과 등록된 날짜별 예외로 계산한다. 미등록 미래 예외는 보장하지 않는다고 안내한다. '지금' 기본값이 30분 격자와 맞지 않을 경우 실제 현재 시각을 유지할지 스냅할지는 구현 전 별도 확인이 필요하다.
7. **기술 스택:** **Next.js + TypeScript**, **Cloudflare 배포**, **네이버 지도 API**, **Supabase PostgreSQL + PostGIS / Auth / Storage** 확정. Next.js의 Cloudflare 런타임/배포 어댑터 호환성, 네이버 지도 다크 테마 지원 여부는 구현 전 기술 검증한다. 검증 없이 프레임워크를 임의 변경하지 않는다.
8. **초기 데이터:** 직접 검증한 실제 장소 **30개**를 최초 공개 목표로 한다.

**DB/API 주의:** 이전 검색 응답의 `coverageStatus: full|partial|unknown`은 `closed`를 포함하도록 확장해야 한다. 부분 영업시간의 정렬값(선택 구간과 실제 영업 구간의 교집합 총 분)을 계산·반환 또는 서버 내부 정렬 키로 사용한다. `unknown`과 `closed`는 별도 상태이며 혼합하지 않는다. 페이지네이션은 그룹·정렬 순서를 유지해야 한다.
