# 페이지 명세: 관리자 장소 등록·편집 (`/admin/places/:placeId/edit`, `/admin/places/new`)

> 경로: `/admin/places/:placeId/edit` (편집), `/admin/places/new` (신규 직접 등록)  
> 상태: [MVP] 1차 구현 대상  
> 대상 플랫폼: 데스크톱 웹  
> 레이아웃: 관리자 셸 (사이드바 유지 + 폼 섹션 스크롤 화면)

---

## 1. 페이지 목적 및 접근 권한

### 1.1 페이지 목적
- 관리자가 개별 장소의 기본 정보, 좌표, 요일별 정기 영업시간, 날짜별 예외, 편의시설 태그, 그리고 **관리자 전용 장소 사진**을 직접 등록하고 수정한다.
- 공식 데이터 수정 시 변경 전후 스냅샷을 `place_change_history`에 안전하게 기록한다.

### 1.2 접근 권한
- **관리자 전용 (`profiles.role = 'admin'`)**
- 관리자 외 접근 불가.

---

## 2. UI 구성과 사용자 동작

### 2.1 상단 액션 바
- `[< 장소 목록으로]` 뒤로가기 링크 (미저장 내용 있을 시 이탈 확인).
- 타이틀: 신규 등록인 경우 `"신규 장소 직접 등록"`, 수정인 경우 `"장소 편집: [장소명]"`.
- 우측 상단: **[변경 사항 저장]** (Primary Blue 버튼).

### 2.2 섹션 1: 기본 정보
1. **장소명 (필수)**: 텍스트 입력창.
2. **카테고리 (필수)**: 8대 대분류 중 1개 선택 드롭다운.
3. **주소 및 좌표 (필수)**:
   - 주소 검색 팝업/버튼을 통해 도로명/지번 주소 입력.
   - 위도(`latitude`), 경도(`longitude`)가 자동 채워지며, 미세 조정 가능.
   - 시·도(`province`), 시·군·구(`city_district`) 자동 파싱.
   - 상세 주소(층, 호수) 텍스트 입력.
4. **부가 정보**:
   - 전화번호, 공식 웹사이트 URL, 네이버 장소 ID(선택).

### 2.3 섹션 2: 검증 상태 및 실확인 관리
- **검증 상태 선택**: 라디오 버튼 (`verified` / `needs_check` / `unverified`).
- **마지막 실확인일**: 날짜 선택 픽커 및 시간.
- **안내**: *"단순 데이터 오탈자 수정은 확인일을 갱신하지 마시고, 관리자가 실제 영업시간을 새로 확인한 경우에만 확인일을 갱신해주세요."*

### 2.4 섹션 3: 요일별 정기 영업시간 (DB.md §3.5)
- **일괄 설정 편의 기능**:
  - `[24시간·연중무휴]`: 7개 요일 모두 `open_24h`로 원클릭 변환.
  - `[매일 동일한 시간 적용]`: 첫 번째 입력 요일의 시간을 7개 요일에 복사.
- **요일별 7개 행 (월~일)**:
  - 요일별 상태: `영업(open)` / `24시간(open_24h)` / `휴무(closed)` / `미확인(unknown)`.
  - `open`일 때 영업 구간 입력:
    - 시작 시간(`start_time`), 종료 시간(`end_time`).
    - 종료 시간이 자정을 넘기는 경우 **[익일 체크박스(`end_day_offset = 1`)]**.
    - 브레이크타임이 있는 경우 `[+ 구간 추가]` 버튼으로 복수 구간 입력.
    - *유효성 검사: 같은 날 및 전날 심야 구간과의 시간 겹침 발생 시 인라인 경고.*

### 2.5 섹션 4: 날짜별 예외 스케줄 (DB.md §3.6)
- 명절, 공휴일, 특정일 임시 휴무 또는 특별 영업시간 관리:
  - `[+ 예외 날짜 추가]` 버튼.
  - 날짜 선택(`local_date`), 예외 상태(`closed`, `open_24h`, `open`, `unknown`), 사유 메모(예: "추석 연휴 휴무").
  - `open`인 경우 예외 시간 구간 설정.
  - *안내: 특정 날짜의 예외는 그 날의 정기 스케줄 전체를 대체합니다.*

### 2.6 섹션 5: 장소 사진 관리 (관리자 전용, DB.md §3.10)
- **특징**: **장소 사진은 오직 관리자만 등록·수정·삭제 가능**. (일반 회원 업로드 불가)
- **사진 업로드 컴포넌트**:
  - 파일 드래그앤드롭 영역 또는 파일 선택 버튼.
  - 허용 형식: JPEG, PNG, WebP (장당 최대 5MB, 서버 검증).
- **사진 썸네일 그리드**:
  - 등록된 사진 목록 카드 렌더링.
  - **대표 사진 지정**: `sort_order`가 가장 낮은 사진이 대표 사진이 됨. 카드를 드래그하여 순서 변경 가능(또는 [대표 사진으로 설정] 버튼).
  - **사진 삭제**: 사진 카드 내 [삭제] 아이콘 클릭 시 DB 메타데이터 및 Supabase Storage 실제 파일 동시 삭제.

### 2.7 섹션 6: 표준 태그 연결
- 관리자 정의 표준 태그 목록(시설·서비스 / 분위기·특징) 체크박스 그리드.
- 장소에 연결할 태그 다중 선택.

## 3. DB 연동 및 API

### 3.1 호출 API
- `POST /api/admin/places` (신규 등록)
- `PATCH /api/admin/places/:placeId` (장소 정보 수정)
- `POST /api/admin/places/:placeId/photos` (사진 업로드)
- `DELETE /api/admin/places/:placeId/photos/:photoId` (사진 삭제)

### 3.2 트랜잭션 및 이력 기록 (DB.md §8.2, §3.12)
- 장소 기본 정보 및 요일별 스케줄, 날짜별 예외 수정은 **단일 트랜잭션**으로 원자적 커밋.
- 수정 완료 시 `place_change_history`에 `changed_by = auth.uid()`, `before_data`, `after_data` 스냅샷 자동 생성.
- `places.location`은 `ST_SetSRID(ST_MakePoint(longitude, latitude), 4326)::geography`로 자동 동기화.

## 4. 예외 상태 (Error States)

### 4.1 영업시간 검증 오류
- 시작 시간과 종료 시간이 동일하거나, 익일 체크 없이 종료 시간이 시작 시간보다 앞선 경우:
  - 에러 메시지: `"유효하지 않은 영업시간 구간입니다. (종료 시간이 자정을 넘기면 '익일'을 체크하세요)"`
- 같은 날에 영업 구간이 서로 겹치는 경우 저장 차단.

### 4.2 사진 업로드 실패
- 5MB 초과 파일 또는 허용되지 않은 확장자/MIME 타입 업로드 시 에러 토스트 표시.
- Storage 업로드 실패 시 트랜잭션 롤백.

---

## 5. 완료 조건 (Acceptance Criteria)

1. [ ] 장소명, 카테고리, 좌표, 부가정보 입력 및 수정이 정상 저장된다.
2. [ ] 요일별 영업시간(정기 구간, 익일 종료, 24시간, 휴무, 미확인)이 정확히 저장 및 검증된다.
3. [ ] 날짜별 예외 스케줄 추가, 수정, 삭제가 정상 작동한다.
4. [ ] 관리자 전용 사진 업로드, 대표 사진 순서 변경, 삭제(스토리지 파일 포함)가 정상 처리된다.
5. [ ] 장소 저장 시 `place_change_history`에 변경 이력이 기록된다.
