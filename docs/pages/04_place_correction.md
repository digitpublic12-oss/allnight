# 페이지 명세: 기존 장소 정보 수정 제보 패널

> 경로: `/place/:placeId` 내 '정보 수정 제보' 클릭 시 진입  
> 상태: [MVP] 1차 구현 대상  
> 대상 플랫폼: 데스크톱 웹  
> 레이아웃: 전면 카카오 지도 유지(해당 장소 중심) + 왼쪽 400px 프리필 폼 패널

---

## 1. 페이지 목적 및 접근 권한

### 1.1 페이지 목적
- 기존에 등록된 장소의 변경된 영업시간, 전화번호, 휴무일, 또는 폐업 여부 등의 오류를 사용자가 제보하여 정보의 정확성을 유지한다.
- 기존 장소의 현재 정보가 미리 입력된 상태에서 수정할 부분만 손쉽게 변경할 수 있도록 편의를 제공한다.

### 1.2 접근 권한
- **모든 사용자 접근 가능 (비회원, 로그인 회원, 관리자 공통 허용)**
- 로그인하지 않은 비회원도 장소 오류 제보를 자유롭게 제출할 수 있다.

---

## 2. UI 구성과 사용자 동작

### 2.1 폼 기본 구조 (SITEMAP.md §6, PRD.md §8.2)
- **미리 채워진 폼 (Pre-filled Form)**: 해당 장소의 현재 DB 데이터(장소명, 카테고리, 주소, 요일별 영업시간, 전화번호, 웹사이트, 태그)가 입력 필드에 기본값으로 세팅된 상태로 렌더링.
- **헤더**:
  - `[< 장소 상세로]` 뒤로가기 버튼: 클릭 시 입력 취소 후 장소 상세 패널로 복귀. 수정된 내용이 존재할 경우 이탈 확인 모달 노출.
  - 타이틀: `"장소 정보 수정 제보"`.
  - 서브 타이틀: `대상 장소: [장소명]`.
  - 안내 문구: `"제안해주신 수정 내용은 관리자 확인 후 공식 정보에 반영됩니다."`

### 2.2 입력 및 수정 필드
1. **폐업 / 심야 영업 중단 신고 (체크박스)**:
   - 폼 최상단에 `"이 장소는 폐업했거나 더 이상 심야 영업을 하지 않습니다"` 체크박스 제공.
   - 체크 시 영업시간 폼 비활성화 및 폐업 사유 입력란 활성화.
2. **장소명 및 카테고리**:
   - 변경이 필요한 경우 직접 텍스트 수정 및 8대 카테고리 중 다른 카테고리로 변경 선택 가능.
3. **위치 및 주소**:
   - 이전/주소 변경이 발생한 경우 주소 검색 버튼을 통해 새 주소 지정 가능.
4. **영업시간 수정 (핵심 제보 항목)**:
   - 7개 요일별(월~일) 스케줄 테이블이 기존 등록 상태대로 표시됨.
   - 사용자가 실제와 달라진 특정 요일의 시간(`start_time`, `end_time`), 24시간 여부, 정기 휴무 여부를 변경.
   - 복수 구간(브레이크타임) 추가/삭제 가능.
5. **부가 정보**:
   - 전화번호, 웹사이트 URL, 편의시설 태그 수정.
6. **수정 사유 및 근거 (필수 권장)**:
   - 텍스트 입력창 (`textarea`):
     - 예: `"현장 확인 결과 간판에 영업시간이 02:00까지로 변경되어 있었습니다."`
     - 관리자가 진위 여부를 판단하는 데 필요한 구체적 근거를 작성하도록 유도.
7. **제보자 연락처**:
   - 회원은 자동 연결, 비회원은 선택적 이메일 입력.

### 2.3 하단 제출 영역
- **[수정 제안 제출하기] 버튼**:
  - 변경된 항목이 전혀 없는 경우: 버튼 클릭 시 `"수정된 정보가 없습니다. 변경 사항을 입력해주세요."` 안내.
  - 변경 사항이 있는 경우: 제출 클릭 시 `POST /api/submissions` 호출.
- **제출 성공 시**:
  - 접수 완료 화면 또는 성공 토스트 표시:
    - `"정보 수정 제보가 접수되었습니다. 관리자 검토 후 반영됩니다."`
  - 장소 상세 패널(`02_place_detail.md`)로 복귀하며, 해당 장소 상단에 **'정보 수정 제보 접수'** 주의 표시가 즉시 노출됨.

## 3. DB 연동 및 API

### 3.1 호출 API
- `POST /api/submissions`
  - 요청 본문:
    ```json
    {
      "type": "correction",
      "placeId": "uuid-target-place",
      "proposedData": {
        "isPermanentlyClosed": false,
        "name": "새벽집 카페 강남점",
        "phone": "02-999-8888",
        "schedule": [
          { "weekday": 1, "status": "open", "intervals": [{ "start": "18:00", "end": "01:00", "endDayOffset": 1 }] }
          // 변경된 스케줄 데이터
        ],
        "correctionReason": "영업시간이 03시에서 01시로 단축되었습니다."
      },
      "guestEmail": "visitor@example.com"
    }
    ```

### 3.2 DB 저장 및 상태 불변조건 (DB.md §3.7, §8.3)
1. **수정 제보가 제출되어도 기존 `places` 및 영업시간 테이블의 공식 데이터는 절대 즉시 변경되지 않음.**
2. `submissions` 테이블에 `type = 'correction'`, `status = 'received'`, `place_id = :placeId`로 레코드 삽입.
3. 대상 장소의 `has_pending_correction` 상태가 `true`로 평가되어(뷰 또는 트리거), 장소 상세 화면에 즉시 주의 경고가 노출됨.

---

## 4. 예외 상태 (Error States)

### 4.1 변경 내용 없음
- 기존 장소 데이터와 비교하여 제안된 데이터에 변경 사항이 없는 경우:
  - 제출을 차단하고 `"기존 정보와 다른 변경된 내용을 하나 이상 입력해주세요."` 안내.

### 4.2 작성 중 이탈 (Dirty State Exit)
- 일부 필드를 수정한 뒤 [뒤로가기] 또는 외부 클릭 시:
  - `"수정 제보 작성 중인 내용이 있습니다. 취소하시겠습니까?"` 모달 표시.

---

## 5. 완료 조건 (Acceptance Criteria)

1. [ ] 장소 상세에서 '정보 수정 제보' 클릭 시 해당 장소의 기존 정보가 폼에 정확히 채워진 상태로 열린다.
2. [ ] 비회원도 로그인 없이 수정 제보를 작성하고 제출할 수 있다.
3. [ ] 폐업 신고, 영업시간 변경, 전화번호 변경 등 각 필드가 정상 작동한다.
4. [ ] 제출 즉시 공식 장소 데이터는 변경되지 않으며, `submissions` 테이블에 `correction` 유형으로 접수된다.
5. [ ] 제보 접수 후 장소 상세로 복귀 시 '정보 수정 제보 접수' 주의 문구가 즉시 표시된다.
6. [ ] 폼 수정 후 취소 이탈 시 확인 대화상자가 표시된다.
